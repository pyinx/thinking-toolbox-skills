# thinking-toolbox · 思维工具箱

个人使用的多思维模型协同分析技能。围绕一个值得深思的问题，**代理收集各模型的问题并集中向你提问**，
联网取证后让多个思维模型分别作答，再交叉讨论、汇总成一份综合结论，并把每次问答自动归档到 `history/`。

## 六步流程

```
1 提出问题 → 2 问题澄清（代理收集） → 3 联网取证（按需） → 4 各模型作答 → 5 集体讨论 → 6 综合结论
```

| 步 | 做什么 | 细则 |
| --- | --- | --- |
| 1 提出问题 | 一句话确认议题 + 标注边界（时间尺度/主体范围） | `SKILL.md` §2 |
| 2 问题澄清 | **各模型只提问题、由主 skill 归并去重，一次性问你（≤4 问，单轮）** | `references/clarification-protocol.md` |
| 3 联网取证 | 先写要查的 3 个变量，检索 ≤3 轮、采纳事实 ≤5 条，逐条标来源 | `references/evidence-protocol.md` |
| 4 各模型作答 | 闭门独立作答，按相关度降序，默认 ≤300 字/模型 | `SKILL.md` §4 |
| 5 集体讨论 | 只允许「张力对」发言，禁止复述，收敛判定必须给结论 | `references/deliberation-protocol.md` |
| 6 综合结论 | 共识 / 分歧 / 盲区 / 主判断 / 推翻条件 / 下一步 | `SKILL.md` §6 |

**为什么第 2 步要代理收集**：若每个模型各自追问，一次分析会产生 10+ 轮往返。
主 skill 把各模型的问题映射到 12 个固定「信息槽位」去重合并，只问最影响结论的 4 个，
且必须通过四项准入测试（多模型会用 / 会改结论 / 低成本 / 无已有答案）。

## 27 个思维模型

第一性原理、系统思维、深度思维、逆向思维、批判思维、战略思维、产品思维、预测思维、长期主义、价值主义、
孙子兵法与三十六计、毛选、芒格、纳瓦尔、概率（贝叶斯）、二阶、经济学、辩证、复利、利他、时光机、终局、周期、
环境、人脉、奥卡姆剃刀、宏观。

**其中 6 个有 `references/` 深内容**（避免"徒有其表"）：

| 模型 | 深内容 |
| --- | --- |
| 孙子兵法与三十六计 | 十三篇要点卡、36 计逐计四格（前提/要点/**失败征兆**/战例）、20 项算战 checklist |
| 毛选 | 矛盾论两段判定程序、调查研究协议、持久战三阶段判据 |
| 芒格 | 25 种误判心理学逐条（定义/场景/**反制动作**）、格栅最小集、能力圈四问 |
| 纳瓦尔 | 专长四问、三种杠杆对照、所有权结构、四种运气升级路径、财富/幸福分离 |
| 概率（贝叶斯） | 三步法、似然比强度表、基准率校正算例、证据独立性、期望值决策 |
| 预测 | 五环链条（基准率→驱动力→反作用力→拐点信号→证伪条件）、五环自检 |

**防注水机制**：每个 reference 都必须在 SKILL.md 里写明「读完后回答必须出现什么」。
例如读过 36 计详解，回答必须含 ①选用计名 ②施用要点 ③失败征兆三段——
缺任一项等于没读。没有回填要求的 reference 不会被真正使用。

## 用法示例

- `用思维工具箱分析：要不要 all in AI 创业` —— 自动匹配 3~7 个模型
- `帮我想想我的事业` —— 信息不足，先反问几个最高信息增益的问题再匹配
- `用芒格和第一性原理分析 X，不要产品思维` —— 指定 + 排除
- `除了产品思维，全部模型都上` —— 全部−排除（27 减 1）
- `全部模型看 X` —— 27 个全开（按相关度排序，每模型 ≤150 字，聚合优先）
- `这局该用孙子兵法还是芒格？` —— 命中分工句，走对应模型

## 分发（软链到宿主）

```bash
# 如需分发到其他宿主：
# ln -s <本目录> ~/.claude/skills/thinking-toolbox
# ln -s <本目录> ~/.agents/skills/thinking-toolbox
```

**只软链主目录，切勿单独软链 `subskills/` 内任何目录**——subskill 是被主 skill 读取的资料，
嵌套目录不会被宿主注册；若被单独软链会污染全局技能列表。

### 与独立技能 deep-thinking 的关系

本技能是**多模型并行拼盘**形态（"多角度看看""几个模型一起想"）；
独立技能 `deep-thinking` 是**单主因果链深挖**形态（"帮我想透""深挖一层"）。
两者形态互斥，按用户措辞选择，不叠加。

## 验收

```bash
python3 scripts/validate.py
```

12 项检查，全部无 FAIL 才算通过。支持 `--only <id>...` 与 `--verbose`。

## history 说明

- 每个问题一个文件：`history/YYYY-MM-DD/HHMM-<问题slug>.md`；追问追加为「追问 N」小节。
- `history/INDEX.md` 是检索入口：说"上次聊过什么"时先读它，不要凭空回忆。
- 默认 `history/*` 被 .gitignore 忽略（个人问答记录不入库）。
- 归档含人名/公司/薪酬/健康等敏感信息且用户未授权时，写入前会先征得同意。
