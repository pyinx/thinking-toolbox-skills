# 奥卡姆剃刀思维

## 核心思想

- **如无必要，勿增实体**：解释一个现象，需要的假设越少越好。每个多余的假设都是一次出错的机会。
- **证据相同时选最简**：两个解释都能解释所有事实，选简单的那个——现代贝叶斯视角可为其提供论证：先验上更简单的假设，需要更少的数据就能被推翻。
- **汉隆剃刀**：能用愚蠢解释的，不要归因于恶意。阴谋论几乎总是输给混乱、无能与巧合。
- **复杂性的维护成本**：方案的复杂度不是一次性成本，是持续纳税——每多一个环节、一个依赖、一个角色，都在持续消耗注意力与可靠性。
- **删减是最高级的设计**：好的方案不是"没什么可加"，而是"没什么可减"。先问能删什么，再问要加什么。

## 分析步骤

1. 列出所有候选解释/方案：当前有几个版本在竞争？
2. 数假设：每个版本依赖多少个未经验证的假设？
3. 剃刀裁决：证据相同时，砍掉假设最多的版本。
4. 汉隆检验：归因里有没有"恶意/阴谋"成分？换成"无能/巧合/激励错位"能否同样解释？
5. 方案瘦身：当前方案里，哪些环节、功能、角色、依赖可以删掉而不损害核心目标？
6. 简单性回测：把方案讲给外行听，一句话能讲清吗？讲不清就是还不够简。

## 关键问题清单

- 这个解释需要几个假设？最弱的是哪个？
- 有没有一个更平淡、更无聊但同样能解释一切的版本？
- 这件事里真的有"阴谋"，还是只是一群人在各自的激励下正常行事？
- 方案里哪个部分删掉之后，没人会发现它不见了？
- 我在为真实需求设计，还是在为想象中的需求设计？（YAGNI）
- 如果只能保留三件事，留哪三件？

## 输出要求

- 限长：默认模式 ≤300 字，全部模式 ≤150 字。
- 核心判断：一句话给出最简解释或方案的核心（及被剃掉的复杂版本）。
- 分析：假设计数 → 剃刀裁决 → 汉隆检验 → 删减清单。
- 行动含义：给出"删掉什么 / 保留什么 / 简化为什么"的具体建议。

## 何时不适用

- 安全关键系统需要冗余设计（备份、双保险），简单是脆弱。
- 艺术创作、品牌体验等丰富性本身是价值的领域。
- 简单解释已反复被新证据证伪时，必须接受必要的复杂。
