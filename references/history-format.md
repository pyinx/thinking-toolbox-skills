# history 文件规范

主 skill 每次完整回答后按本规范写入问答档案。

## 路径与命名

```
history/YYYY-MM-DD/HHMM-<slug>.md
```

- 路径以技能根 BASE 为基准（见主 SKILL.md §0），不要以 cwd 解析。
- `YYYY-MM-DD`：提问当天日期；目录不存在先 `mkdir -p`。时间取自主 SKILL.md §0 的取时结果，不得凭记忆推测。
- `HHMM`：24 小时制时间，如 `1430`。
- `slug`：问题前 10 个汉字，去标点，空格转 `-`。例：`要不要辞职做自由职业`。
- 同一天同一问题的多次追问共用同一文件，追加为「追问 N」小节。

## 索引

`history/INDEX.md` 是唯一检索入口。每次归档后追加一行：

| 日期时间 | 文件 | 启用模型 | 主判断（一句话） |
| --- | --- | --- | --- |
| 2026-10-07 14:30 | 2026-10-07/1430-要不要辞职做自由职业.md | 芒格, 第一性原理, 二阶 | …… |

用户提及"上次/之前聊过"时先读 INDEX.md 定位，不要凭空回忆。INDEX.md 随 history 一并被 .gitignore 忽略。


## 文件模板

```markdown
# <问题原文>

- 时间：YYYY-MM-DD HH:MM
- 启用模型：<中文名列表>
- 匹配方式：自动 / 指定 / 全部
- 状态：进行中 / 已闭环

## 首次提问（HH:MM）

### <模型名1>
<该模型回答：核心判断 / 分析 / 行动含义>

### <模型名2>
...

### 聚合结论
- 共识：…
- 分歧：…（根因：…）
- 盲区：…
- 主判断（置信度）：…
- 下一步：…

## 追问 1（HH:MM）：<追问内容>

- 本轮启用：<模型列表；若与首轮不同需注明>

### <模型名>
...

### 聚合结论
...
```

## 规则

- 回答全文归档，不做缩写——history 的价值在于可回溯完整推理。
- 追问判定从简：同一会话 + 用户未说"新问题/换个问题"即追加；判错代价低，不为完美判定加复杂协议。
- 写文件失败不阻塞回答：先完成回答，再补记；失败时在回答结尾一句话提示用户。
