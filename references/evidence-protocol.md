# 第 3 步 联网取证协议

主 skill 在第 4 步之前完成事实取证。**先取证再作答**，避免各模型各自联网导致发散。

## 何时执行

判定标准是**结论是否依赖会变的事实**，而不是"用了哪个模型"。

### 取证优先的 5 个模型

结论若出现具体数字而无来源，即视为违规：

| 模型 | 需要取证的内容 |
| --- | --- |
| forecasting | 基准率、趋势的历史数据 |
| cycles | 周期位置指标（估值分位、杠杆率、库存等） |
| macro-thinking | PEST 各项的当前取向与数据 |
| value-thinking | 价格、估值数据 |
| bayesian-thinking | 基准率统计值 |

### 强制取证的情形

价格、政策、法律条文、市场数据、人事变动、产品版本、竞争格局、任何带年份的数字。

### 跳过取证的情形

1. 纯方法论议题（"复利怎么算""第一性原理怎么用"）
2. 用户明确要求不研究
3. 检索预算用尽
4. 议题不依赖任何外部事实

## 执行流程

### 1. 先写变量清单（不得跳过）

检索**之前**先输出「要查的 3 个关键变量」。这一条能防止"顺便了解一下行业"式发散。

```
要查的变量：1. <X>  2. <Y>  3. <Z>
```

查不到 X 就不去查别的，更不查 X 的邻域话题。

### 2. 预算

- 检索 **≤3 轮**
- 采纳事实 **≤5 条**
- 触及即停。剩余不确定性用第 6 步的置信度表达，而不是继续搜。

### 3. 来源与时效（硬约束）

每条事实必须带来源与时间：

```
【事实】<陈述>（来源：<来源名> · <发布日期或检索日期>）
```

**无来源的数字禁止写进第 4 步的「分析」段**，只能进「信息缺口」段。

### 4. 失败降级

搜不到就显式写：

```
【信息缺口】<搜不到的 X>；影响：<哪一步的判断会变>；置信度由 高 → 中
```

**严禁用"根据常识/一般而言/通常来说"填补**——这是联网模式最常见的退化，
会让整个取证步骤变成走过场。宁可承认不知道。

### 5. 防发散硬规则

取回的网页只作为**事实来源**，不作为"更多观点"。

- 禁止把检索到的行业观点、分析家预测写进第 4 步的分析段。
- 原因：那会给 27 个模型之外**凭空多出一个没被调度的"媒体视角"**，破坏 §2.2 的匹配单一事实源。

## 输出格式

```markdown
## 事实基础
- 【事实】<陈述>（来源：<来源> · <日期>）
- 【事实】<陈述>（来源：<来源> · <日期>）
- 【信息缺口】<X>；影响：<哪一步判断会变>；置信度由 高 → 中
```

**推断与事实必须分行**，禁止把事实塞进"分析"里冒充推理。

## 与 forecasting 的边界

本步骤只解决「事实是否存在、是否过期」，**不解决趋势推演**。
做趋势推演是 forecasting 模型自己的职责（读它的 `references/base-rates-and-falsification.md`）。

不要用多轮追问式调研把第 3 步扩展成一次深度研究——那会越界并拖慢流程。
需要深度推演时，让 forecasting 模型在第 4 步自行使用其 reference。
